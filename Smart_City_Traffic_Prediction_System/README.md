# Smart City Traffic Prediction System

## 1. Project overview
An end-to-end Python, machine-learning and Streamlit demonstration that explores traffic patterns and predicts **Low / Medium / High** congestion for a selected location and future time scenario.

**Dataset notice:** `data/traffic_data.csv` is a reproducible synthetic demonstration dataset containing 6,000 records. It is not official Chennai traffic sensor data and must not be represented as measured real-world traffic. Replace it with validated sensor, GPS, or open-government data before operational use.

## 2. Features
- Data validation, cleaning, duplicate removal, and datetime feature engineering
- EDA for hourly traffic, location comparison, congestion distribution, and location-hour heatmap
- Random Forest classification pipeline with one-hot encoding and scaling
- Hold-out evaluation: accuracy, per-class precision/recall/F1, and confusion matrix
- Interactive Streamlit dashboard with filters, charts, scenario prediction, and CSV export

## 4. Setup (Windows)
Open Command Prompt or the VS Code terminal in this project folder.

```bash
py -3.11 -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

If `py -3.11` is unavailable, use `python -m venv .venv` with an installed supported Python version.

## 5. Run the project
**Step 1 — inspect and preprocess data**
```bash
python src_preprocess.py
```

**Step 2 — train and evaluate the model**
```bash
python train_model.py
```
This creates `models/traffic_congestion_model.joblib` and `models/metrics.json`.

**Step 3 — launch the dashboard**
```bash
streamlit run app.py
```
Open the local URL printed in the terminal (usually `http://localhost:8501`).

## 6. Dataset dictionary
| Column | Meaning |
|---|---|
| timestamp | Observation date and time |
| location | Road/area label |
| vehicle_count | Vehicles observed in the 15-minute synthetic interval |
| road_capacity | Demonstration reference capacity for the location |
| weather | Simulated weather category |
| special_event | 1 if a special event is simulated, otherwise 0 |
| congestion_level | Target class: Low, Medium, or High |

The target is derived from vehicle_count / road_capacity: below 0.55 = Low; 0.55 to below 0.90 = Medium; 0.90 or above = High. The model does not use future vehicle_count as an input; it predicts from time, location, weather, road capacity, and event context.

## 7. Model and evaluation
A scikit-learn Pipeline applies one-hot encoding to location/weather, standardizes numeric inputs, and trains a Random Forest classifier. Data is split into 80% train and 20% test with stratification and a fixed random seed. Review the generated `models/metrics.json`; do not assume a target accuracy before training.

## 8. Suggested real-world upgrade
1. Obtain timestamped traffic counts from road sensors, CCTV analytics, GPS/vehicle probe feeds, or a government open-data portal.
2. Document source, licensing, collection interval, coverage, missingness, and sensor calibration.
3. Define congestion labels using an approved traffic-engineering standard or measured speed/travel-time thresholds.
4. Use chronological train/validation/test splits to avoid time leakage.
5. Add lagged traffic volume/speed features and compare time-series baselines (seasonal naive, linear models, gradient boosting).
6. Monitor drift, sensor outages, and per-location performance before deployment.

## 9. Limitations
The synthetic dataset is designed to demonstrate the workflow, not to provide actual traffic forecasts. Model confidence is not a guarantee of correctness. The dashboard's future scenario prediction is only as reliable as the training data and target definition.
